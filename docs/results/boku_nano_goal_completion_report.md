## 健康状態と主要評価値

| 指標 | 参考値 | 実測値 | 判定 |
|---|---:|---:|:---:|
| Syntax-valid率 | 80%以上 | 84,546 / 84,550（99.9953%） | 参考値以上 |
| 通常テストpass@1 | 30%以上 | 24,038 / 24,040（99.9917%） | 参考値以上 |
| 全体pass@1 | 規定なし | 84,434 / 84,550（99.8628%） | 参考 |
| 組合せ汎化率 | 規定なし | 13,397 / 13,400（99.9776%） | 参考 |
| 固定430問のpass@5 | 規定なし | 425 / 430（98.8372%） | 参考 |

全テスト問題には20件以上のhidden入力を使用した。通常、組合せ汎化、日本語言い換え、同一操作の反復では各64件、境界値では各30〜31件を実行した。コード候補作成時の41入力とランダム評価入力320件の完全一致は0件である。

## 学習前後と追加比較

| 比較 | Validation loss | Syntax-valid率 | pass@1 | 解釈 |
|---|---:|---:|---:|---|
| ランダム初期モデル | 7.759890 | 0 / 430 | 0 / 430 | Python構文を生成できず、学習前の能力は確認されなかった。 |
| 3エポックモデル | 0.393880 | 428 / 430 | 424 / 430 | 学習後に構文生成とhidden test通過能力を獲得した。 |
| 10エポックモデル | 0.408651 | 84,301 / 84,550 | 83,058 / 84,550 | 3エポックより1,376件少なく、追加学習で悪化した。 |

ランダム初期モデル対3エポックモデルに加え、3エポック対10エポックの2本目の比較も実施した。今回の条件では、validation lossと5テストすべてのpass@1から3エポックモデルを採用するのが妥当である。

## 失敗の確認

| 区分 | 不合格 | 主な内容 |
|---|---:|---|
| 通常テスト | 2 | 指示にないsortやfilterを追加 |
| 組合せ汎化テスト | 3 | 操作の余分な反復、`>=`と`>`の取り違え |
| 日本語言い換えテスト | 6 | 偶奇、二乗、先頭・末尾の未学習表現を誤解 |
| 同一操作の反復テスト | 103 | 反復回数の省略、途中で別操作へ変化 |
| 境界値テスト | 2 | 通常テストと同じ2生成を別入力で再評価した失敗 |

失敗形式は実行結果不一致112件、構文エラー4件、タイムアウト0件である。改善優先順位は、同一操作の反復、日本語言い換え、比較演算子境界の順とする。

## データ漏洩検査

| 検査対象 | 結果 |
|---|---|
| 意味AST分割 | 訓練9,646、検証1,202、通常テスト1,202の`spec_id`と正規化意味ASTは集合内・集合間とも重複なし。組合せ汎化670 ASTも事前に分離した。 |
| Pythonコード | 訓練・検証・通常・組合せ汎化・反復の全277,440候補は集合内完全重複0件。5集合間10通りの完全一致も0件。 |
| hidden入力 | 評価用ランダム5集合、計320入力はコード作成時の41入力と完全一致0件。5評価集合相互も完全一致0件。 |
| 日本語言い換え | `test_only`30表現は訓練とトークナイザ学習へ含めず、評価専用とした。教師による全文言い換えも`split=train`かつ`dictionary=train`だけを対象とした。 |
| 評価中の不変性 | 評価ZIPは実行前後でSHA-256が一致し、評価データの変更はなかった。 |

保存済み検査結果では漏洩を示す完全一致は確認されていない。クリーンな取得状態では、再実行手順に従ってGit管理ZIPを展開した後、同じ検証器で再確認する。

## 使用物の由来

| 対象 | 由来・固定情報 |
|---|---|
| 意味AST・Pythonコード・テスト入力 | リポジトリ内の仕様と生成スクリプトから作成した合成データ。インターネット上のコードは使用していない。 |
| 日本語指示 | ルール生成96,510件と、教師モデル由来96,390件からなる。最終訓練データは合計192,900件。 |
| 教師モデル | `Qwen/Qwen3-4B-AWQ`、revision `74d4bd2bd4bff9cafc9345221320bffb08b406a3`、AWQ 4-bit。訓練データ作成時だけ使用した。 |
| トークナイザ | `tokenizers` 0.21.4による独自BPE、語彙2,048。訓練データだけから作成。SHA-256 `6840a392...27293`。 |
| 学生モデル | 独自Decoder-only Transformer、15,735,168 parameter、seed `20260925`、3エポック。SHA-256 `5623f066...cf0e`。 |
| ソフトウェア | Python 3.12.12、PyTorch 2.13.0+cu130、NumPy 2.5.3、PyYAML 6.0.3、safetensors 0.8.0、tokenizers 0.21.4。`pyproject.toml`と`uv.lock`で依存関係を管理。 |

教師モデルのライセンスと第三者権利は別問題である。課題仕様にはApache License 2.0の教師候補として記載されているが、公開時にはモデルのLICENSE、`THIRD_PARTY.md`、Dataset Card、Model Cardを同梱して最終確認する必要がある。

## 再実行手順

データ生成から評価までの順序、必要なZIP展開、Hugging Faceからの教師モデル取得、トークナイザと学生モデルの新規学習、5テストと比較評価は、[Boku Nano データ生成から評価までの再実行手順](../procedures/boku_nano_end_to_end_reproduction.md)へ集約した。

標準経路では固定済みの教師言い換えZIPを使うため教師モデルを準備する必要はない。教師出力から再生成する場合はHugging Faceから固定revisionを取得し、形式検査後に機械的に一括採用する。人手承認は再実行の必須工程に含めない。
