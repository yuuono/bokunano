# Boku Nano 15M・1エポックのトークナイザー比較

## 結論

既存BPEと短いpiece用BPEについて、モデル構造、初期seed、訓練データ、epoch数を揃えて学習・評価した。どちらも「約15M」ではなく、正確には15,735,168パラメータのDecoder-only Transformerである。

| 項目 | 既存BPE | 短いpiece用BPE |
|---|---:|---:|
| パラメータ数 | 15,735,168 | 15,735,168 |
| epoch | 1 | 1 |
| 固定5テスト合格 | 84,180 / 84,550 | 84,305 / 84,550 |
| 全体参考合格率 | 99.5624% | 99.7102% |
| 日本語言い換え | 15 / 30 | 20 / 30 |
| 学習系列token | 6,939,466 | 17,281,995 |
| 学習時間 | 48.287秒 | 124.801秒 |

短いpiece用BPEは合計で125件、0.1478ポイント高い。特に組合せ汎化と日本語言い換えが改善した。一方、同一操作の反復は既存BPEが85件高く、短いpiece版は学習系列tokenが2.490倍、学習時間が2.585倍だった。精度差だけでなく計算量を含めると、短いpiece版が全面的に優位とはいえない。

## 評価条件

[共通評価器](../../scripts/model/evaluate_boku_nano.py)を使用し、次の条件を揃えた。

| 項目 | 条件 |
|---|---|
| 評価件数 | 固定5集合、合計84,550件 |
| decoding | greedy、samplingなし |
| 最大生成長 | 160 token |
| context length | 256 token |
| dtype / device | bfloat16 / CUDA |
| signature | solve(xs: list[int], k: int) -> list[int] |
| 実行timeout | 1生成コードの全case合計5秒 |
| 合格条件 | 構文、安全AST、signature、全hidden入力、入力非変更、返値型をすべて満たす |

両モデルとも全生成がEOSで終了し、timeoutは0件だった。

## 日本語言い換え

同じ30件を評価した。

| 比較 | No. |
|---|---|
| 両方合格 | 1, 7, 9, 10, 11, 12, 14, 18, 19, 21, 23, 27, 29, 30 |
| 短いpiece版だけ合格 | 4, 8, 13, 22, 25, 26 |
| 既存BPEだけ合格 | 17 |
| 両方不合格 | 2, 3, 5, 6, 15, 16, 20, 24, 28 |

短いpiece版だけが合格した6件には、奇数の分類、k超過値の切り出し、正値への限定、符号反転、昇順・降順の言い換えが含まれる。既存BPEだけが合格したNo.17は「各数値からkを減らす」である。言い換えの全文と操作対応は[言い換えテスト結果](paraphrase_test_instruction_results.md)を参照。

## 失敗形式

| 形式 | 既存BPE | 短いpiece用BPE |
|---|---:|---:|
| 合格 | 84,180 | 84,305 |
| hidden入力で結果不一致 | 352 | 243 |
| 静的検査不合格 | 16 | 2 |
| 実行時例外 | 2 | 0 |
| timeout | 0 | 0 |

短いpiece版は意味不一致を109件、静的検査不合格を14件、実行時例外を2件減らした。改善数の大半は組合せ汎化に現れた。一方、反復では既存BPEのほうが高く、操作回数の保持には別の傾向がある。

## 判断

同一1エポック条件では、短いpiece用BPEが総合精度と言い換えで上回った。ただし、改善は総合0.1478ポイントに対して学習token 2.490倍、学習時間2.585倍である。

- 日本語言い換えを優先する場合は短いpiece版に利点がある。
- 学習・推論効率を優先する場合は既存BPEが有利である。
- 同一操作の反復では既存BPEが高いため、短いpiece版へ全面移行する根拠にはならない。
- 次の比較ではepoch数ではなく、同一token予算または同一計算量を揃える必要がある。
