# Qwen3-1.7Bブラウザ読み込みの調査（2026-10-07）

## 再現結果

公開Pages `https://yuuono.github.io/bokunano/`をユーザーのChromeの別タブで開き、設定からQwen3-1.7Bを選択し「各要素を二乗してください。」を送信。処理の詳細に以下のエラーが表示された。

```text
Can't create a session. ERROR_CODE: 6, ERROR_MESSAGE: std::bad_alloc
```

QwenのONNX実行セッション作成時のメモリ確保失敗である。Qwenの文章出力やCNLの検査に到達していないため、指示の書き方を変えてもこの原因は解消しない。現在の「指示を見直してください」という共通エラー表示はこのケースに適していない。

## 読み込んでいるモデル

- モデル：onnx-community/Qwen3-1.7B-ONNX
- 固定revision：cc6a06a21d614e9b8e92a6adfab1074d4e7d2438
- ファイル：onnx/model_q4f16.onnx
- ファイルサイズ：1,426,069,098 bytes（約1.33 GiB）
- Transformers.js：4.3.0、device：webgpu、dtype：q4f16
- 実装：web/qwen-worker.jsのpipeline呼び出し

## 原因の確度

実測で確定したのは、セッション初期化でのメモリ確保失敗。どの内部領域で何bytes不足したかまでは今回のエラーだけでは特定できない。Mac全体の物理メモリ不足と断定するものではない。

ダウンロードファイルの大きさと、初期化・実行時に必要なメモリ量は同じではない。ONNXデータの読み込み・解析や実行用の領域が追加で必要になる。GPUで演算しても読み込み処理にCPU側／WebAssembly側のメモリが必要になる。[ONNX Runtimeの公式説明](https://onnxruntime.ai/docs/tutorials/web/large-models.html)ではWebAssemblyの4GB上限などの制約を説明している。ただし、今回その4GB上限に到達したこと自体を計測したわけではない。

0.6B向けの読み込み経路に1.7Bのファイルを指定しただけでは、この環境でロードできなかった。前回の追加時はUIから選択したモデルがworkerに渡ることまでの検証で、1.7Bの実ロードを未検証としていた。今回、その未検証部分での失敗を確認した。

## 調査時点の対応候補（以下の修正前）

1. 当面は動作実績のある0.6Bを使用する。
2. 1.7Bをブラウザで維持するには、重みを外部データ化したONNXや初期化設定などでメモリのピークを下げ、実ロード・生成まで再検証する。成功するとは未確認。
3. Mac上のネイティブ実行はブラウザの読み込み制約と別である。過去の1.7Bの50問評価が実行できていても、ブラウザ版のロード成功を保証しない。

## 修正と実機検証

Qwen3-1.7Bのみ、モデルの構造と重みを分けた外部データ形式に切り替えた。0.6Bは従来のまま。元のONNXには重み1.43GBが埋め込まれていたが、分離版の構造ファイルは318,014 bytes、外部重みは1,425,786,880 bytes。ダウンロード総量はほぼ同じで、巨大な重みをProtobufの内部データとして解析することを避ける。

- 配布元：`Exempliss/Qwen3-1.7B-ONNX-Split`
- 固定revision：`f9b9656836a4315a690d0270f885b0758923bd13`
- 元モデルと分離版を実ダウンロードして、508個すべてのテンソルの型・形状・重みバイト列を照合。一致を確認。
- 外部保存に関するフィールドを除き、611ノードのグラフとモデル情報全体が一致。
- tokenizer.jsonは保存上の書式が違うがJSON内容は一致。他のトークナイザー設定・生成設定は配布ファイルのblob IDが一致。
- [照合結果JSON](qwen17_external_weights_verification.json)と[照合スクリプト](../../scripts/model/verify_qwen_external_weights.py)を保存。モデルの内容や量子化の種類（q4f16）を変えた対応ではない。

ユーザーのMacのChromeでローカルデモを操作し、「各要素を二乗してください。」を送信。ダウンロード・セッション作成・Qwenの生成・CNL検査・Boku15M1epochへの受け渡し・Pythonコード出力まで成功した。Qwenは2回目の生成で検査を通過し、ダウンロード込み127.8秒。Bokuは二乗のコードを出力した。

さらに、読み込みや実行時のエラーでは「指示を見直してください」と表示せず、メモリ確保失敗や読み込み失敗に応じた説明を表示する。元のエラーは「処理の詳細」に保持する。モデル取得量の表示は構造ファイルと外部重みの合計で計算する。

前回のエラー原因はセッション初期化のメモリ確保失敗であり、この形式変更で実機上の読み込みに成功した。内部のピークメモリ量自体は計測していないため、特定のメモリ上限に達したという断定はしない。


再読み込み後、「各要素を絶対値にして、大きい順に並べてください。」でもQwen1.7Bの2回生成（12.5秒）からBokuのコード出力まで成功。キャッシュを使った再ロードも確認した。自動テスト52件もすべて成功。
