# Boku Nano追加評価指標・ランダム初期モデル比較結果

## 実施概要

2026年9月26日に、3エポック学習済みBoku Nanoについて次の追加評価を行った。

1. 正式評価84,550件の既存結果から、Syntax-valid率、Safe-AST率、Signature-valid率、Executable率、pass@1、組合せ汎化率を再集計した。
2. 3エポック学習済みモデルと、学習開始時のseedで再現したランダム初期モデルを、同じ固定430件で比較した。
3. 固定430件について、greedy 1候補と固定seedのtop-p sampling 4候補を使い、pass@5を測定した。
4. 両モデルについて、全24,040件の検証集合でValidation lossを再計算し、最大GPUメモリと生成tokens/sを記録した。

BLEUや参照コードとの文字列一致は主要指標にしていない。生成コードを実際にhidden testで実行した結果を優先する。

## 結論

- 正式評価84,550件における3エポックモデルのpass@1は84,434 / 84,550、99.8628%だった。
- Syntax-valid、Safe-AST、Signature-valid、Executableはいずれも84,546 / 84,550、99.9953%だった。残る4件はPython構文エラーである。
- 組合せ汎化率は13,397 / 13,400、99.9776%だった。
- 固定430件の比較では、学習済みモデルのpass@1は424件、pass@5は425件だった。5候補化で日本語言い換えテストが1件改善した。
- ランダム初期モデルは430件すべてでPython構文を生成できず、Syntax-valid率からpass@5まで0%だった。
- Validation lossは、ランダム初期モデルの7.759890から学習済みモデルの0.393880へ低下した。学習によってコード生成能力を獲得したことを、損失と実行評価の両方で確認できた。
- 2本目の比較では、10エポックモデルのpass@1は83,058 / 84,550、98.2354%となり、3エポックモデルより1,376件、1.6274ポイント低かった。

## 評価指標の定義

| 指標 | 本評価での定義 |
|---|---|
| Validation loss | 検証集合24,040件、教師コードとEOSだけを対象にしたtoken平均loss |
| Syntax-valid率 | 生成コードが`ast.parse`に成功した割合 |
| Safe-AST率 | 既存の安全性検査を通過し、禁止構文、禁止呼び出し、禁止代入などを含まない割合 |
| Signature-valid率 | `solve(xs: list[int], k: int) -> list[int]`を正しく定義した割合 |
| Executable率 | 静的検査後、例外やtimeoutなしで全hidden testを実行できた割合。参照結果との不一致は実行可能として数える |
| pass@1 | greedyによる1回の生成で、全hidden testに合格した割合 |
| pass@5 | greedy 1候補とtop-p sampling 4候補のうち、1候補以上が全hidden testに合格した割合 |
| 組合せ汎化率 | 組合せ汎化テストに対するpass@1 |
| 最大GPUメモリ | Validation loss、pass@1、pass@5測定中のPyTorch最大割当量 |
| tokens/s | GPU生成区間だけを同期計時した、生成token数 / 秒 |

Safe-AST率とSignature-valid率は既存検証器の段階判定を使う。今回の学習済みモデルの静的検査不合格4件はすべて構文解析段階で失敗し、ランダム初期モデルも全件が構文解析段階で失敗した。このため、Syntax-valid、Safe-AST、Signature-validの件数は同じになった。

## 正式評価84,550件の追加集計

正式評価は、全5テストをgreedyで1回ずつ生成したpass@1評価である。

| 指標 | 合格件数 | 割合 |
|---|---:|---:|
| Syntax-valid率 | 84,546 / 84,550 | 99.9953% |
| Safe-AST率 | 84,546 / 84,550 | 99.9953% |
| Signature-valid率 | 84,546 / 84,550 | 99.9953% |
| Executable率 | 84,546 / 84,550 | 99.9953% |
| pass@1 | 84,434 / 84,550 | 99.8628% |
| 組合せ汎化率 | 13,397 / 13,400 | 99.9776% |

Executableだがpass@1で不合格だった112件は、コードを例外なく実行できたものの、少なくとも1件のhidden testで参照結果と一致しなかったレコードである。構文エラー4件と合わせて不合格は116件になる。

テスト別pass@1の詳細と不合格分析は[3エポックモデル評価結果](boku_nano_3epoch_evaluation_results.md)に記録している。

## 比較実験

### 比較条件

| 項目 | 条件 |
|---|---|
| 学習済みモデル | 3エポックモデル、15,735,168 parameters |
| 比較対象 | 同じ構造を学習seed `20260925`で初期化した学習前ランダムモデル |
| 比較集合 | 固定430件 |
| 内訳 | 通常100、組合せ汎化100、日本語言い換え30、同一操作の反復100、境界値100 |
| 選択方法 | record IDとseed `2026092606`のSHA-256順。日本語言い換えは全30件 |
| 比較集合ID hash | `420c4d098de43c3872a8756cb3114e4dc644740f658e6157a449e3bfa3d01768` |
| pass@1 | samplingなしのgreedy decoding |
| pass@5 | greedy 1候補 + top-p sampling 4候補 |
| sampling条件 | seed `2026092607`、temperature 0.8、top-p 0.95 |
| 最大生成長 | 160トークン |
| hidden test | 通常・組合せ・言い換え・反復は各64件、境界値は各30〜31件 |
| タイムアウト | 1生成コードの全hidden testで5秒 |
| 計算環境 | NVIDIA GeForce RTX 5090、CUDA、bfloat16 |

比較集合は全体性能の正式値を置き換えない。全84,550件のpass@1は前節の正式評価を使い、pass@5とランダムモデル比較だけを同じ固定430件で解釈する。

通常、組合せ汎化、日本語言い換え、同一操作の反復の64入力は、コード作成時のbuild入力と完全一致しない固定seedのランダムhidden入力である。境界値テストは目的上ランダム入力へ置き換えず、空、単一要素、極値、重複、`k`境界などを含む30〜31件の固定hidden入力を使う。すべてのテスト問題を20件以上の、コード作成時とは異なるhidden入力で判定した。

### 全体比較

| 指標 | ランダム初期モデル | 3エポックモデル |
|---|---:|---:|
| Validation loss | 7.759890 | 0.393880 |
| Validation perplexity | 2,344.6463 | 1.4827 |
| Syntax-valid率 | 0 / 430（0.0000%） | 428 / 430（99.5349%） |
| Safe-AST率 | 0 / 430（0.0000%） | 428 / 430（99.5349%） |
| Signature-valid率 | 0 / 430（0.0000%） | 428 / 430（99.5349%） |
| Executable率 | 0 / 430（0.0000%） | 428 / 430（99.5349%） |
| pass@1 | 0 / 430（0.0000%） | 424 / 430（98.6047%） |
| pass@5 | 0 / 430（0.0000%） | 425 / 430（98.8372%） |
| 最大GPUメモリ | 865.9 MiB | 865.9 MiB |
| greedy tokens/s | 6,547.1 | 5,895.3 |
| 5候補全体 tokens/s | 12,609.2 | 12,523.6 |

ランダム初期モデルのgreedy出力430件はすべてEOSへ到達せず、最大生成長160トークンで終了した。そのため生成token数が多く、tokens/sは学習済みモデルよりわずかに高い。これは品質の高さを意味せず、長い系列をまとめて処理したことによる計測上の差である。

| テスト名 | 件数 | ランダムpass@1 | ランダムpass@5 | 3エポックpass@1 | 3エポックpass@5 |

| 通常テスト | 100 | 0 | 0 | 100（100.0000%） | 100（100.0000%） |

| 日本語言い換えテスト | 30 | 0 | 0 | 24（80.0000%） | 25（83.3333%） |
| 同一操作の反復テスト | 100 | 0 | 0 | 100（100.0000%） | 100（100.0000%） |
| 境界値テスト | 100 | 0 | 0 | 100（100.0000%） | 100（100.0000%） |
| 合計・参考値 | 430 | 0（0.0000%） | 0（0.0000%） | 424（98.6047%） | 425（98.8372%） |

固定部分集合に含まれた通常、組合せ汎化、反復、境界値のレコードはpass@1ですべて合格した。pass@5による改善は日本語言い換えテストの1件だけだった。

### pass@5で改善した問題

| 項目 | 内容 |
|---|---|
| 意味仕様 | `combined-000022`、先頭`k`個の切り出し |
| 日本語表現 | 最初のk個を取り出す |
| pass@1 | 不合格。末尾`k`個を返した |
| pass@5 | 4番目候補が合格 |
| 合格コード | `return xs[:k]` |

5候補化による改善幅は430件中1件、0.2326ポイントだった。候補数を増やすだけでは、日本語言い換えの残り5件を解決できていない。モデル自体の表現理解を改善する必要がある。

## 追加比較：3エポック対10エポック

可能な2本目の比較として、既に同じtokenizer、評価ZIP、hidden入力、greedy条件で正式評価済みの10エポックモデルと比較した。pass@5とGPU効率は3エポックモデル対ランダム初期モデルの固定430件だけで測定しているため、この比較では全84,550件のValidation loss、段階別率、pass@1を使用する。

### 全体比較

| 指標 | 3エポック | 10エポック |
|---|---:|---:|
| Validation loss | 0.393880 | 0.408651 |
| Syntax-valid率 | 84,546 / 84,550（99.9953%） | 84,301 / 84,550（99.7055%） |
| Safe-AST率 | 84,546 / 84,550（99.9953%） | 84,301 / 84,550（99.7055%） |
| Signature-valid率 | 84,546 / 84,550（99.9953%） | 84,301 / 84,550（99.7055%） |
| Executable率 | 84,546 / 84,550（99.9953%） | 84,285 / 84,550（99.6866%） |
| pass@1 | 84,434 / 84,550（99.8628%） | 83,058 / 84,550（98.2354%） |

### テスト別pass@1

| テスト名 | 3エポック | 10エポック | 3エポックとの差 |
|---|---:|---:|---:|
| 通常テスト | 24,038 / 24,040（99.9917%） | 23,980 / 24,040（99.7504%） | -58件 |
| 組合せ汎化テスト | 13,397 / 13,400（99.9776%） | 13,334 / 13,400（99.5075%） | -63件 |
| 日本語言い換えテスト | 24 / 30（80.0000%） | 21 / 30（70.0000%） | -3件 |
| 同一操作の反復テスト | 22,937 / 23,040（99.5530%） | 21,743 / 23,040（94.3707%） | -1,194件 |
| 境界値テスト | 24,038 / 24,040（99.9917%） | 23,980 / 24,040（99.7504%） | -58件 |
| 合計・参考値 | 84,434 / 84,550（99.8628%） | 83,058 / 84,550（98.2354%） | -1,376件 |

10エポックではValidation lossと5テストすべてのpass@1が悪化した。低下の86.8%に当たる1,194件は同一操作の反復テストで発生している。今回の設定では追加学習による改善はなく、最終モデルとしては3エポックを採用するのが妥当である。

## 実験の判断

ランダム初期モデルはValidation loss、構文、実行、機能正解のすべてで学習済みモデルを大きく下回った。したがって、3エポックモデルの高いpass@1は、モデル構造や評価器だけから偶然得られたものではなく、学習によって獲得した性能と判断できる。10エポックとの比較からは、学習を長く続ければ性能が上がるわけではなく、Validation lossとテスト別pass@1の両方でモデル選択する必要があることも確認できた。

一方、pass@5の改善は日本語言い換え1件に限られた。現在の課題は探索不足よりも、未学習の日本語表現と同一操作反復の理解にある。今後の改善判断では、候補数を増やした値よりgreedy pass@1を主指標として維持する。
