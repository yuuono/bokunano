# 組合せ汎化テストの方針

## test_suiteの値

テスト集合を表す`test_suite`は、次の5種類に統一する。

```yaml
test_suite: normal | paraphrase | compositional | boundary | repetition
```

| test_suite | テスト集合 |
|---|---|
| `normal` | 通常テスト |
| `paraphrase` | 言い換えテスト |
| `compositional` | 組合せ汎化テスト |
| `boundary` | 境界値テスト |
| `repetition` | 同一操作の反復テスト |

## 前提

現在、24個の単独操作から、操作の順序を区別して1〜3個を組み合わせた意味ASTを12,720件作成している。

この文書で定める670件には、次の`test_suite`を設定する方針とする。

```json
{
  "test_suite": "compositional"
}
```

この抽出ファイルでは、`test_suite: "compositional"`自体がテスト用であることを表すため、`split: "test"`は重複して保存しない。

同じ操作が連続する1,152件は、この670件には含めない。そちらには別の`test_suite`を設定する。

```json
{
  "test_suite": "repetition"
}
```

| 対象 | test_suite | 件数 |
|---|---|---:|
| 選択した5個の2操作ペアと、それを含む3操作AST | `compositional` | 670 |
| 同じ操作が隣接する2操作・3操作AST | `repetition` | 1,152 |

この2集合は混ぜず、評価結果も別々に集計する。

内訳は次のとおりである。

| 操作数 | 件数 |
|---|---:|
| 1個 | 24 |
| 2個 | 552 |
| 3個 | 12,144 |
| 合計 | 12,720 |

現在の12,720件は、1つの意味AST内で同じ単独操作を繰り返さない条件で作成している。そのため、同じ操作が連続する意味ASTは含まれておらず、訓練にも使用しない。

## 同じ操作が連続する意味AST

同じ操作が連続する意味ASTは、組合せ汎化テストには含めない。独立した`repetition`テストとして扱う。

2操作の例：

```json
{
  "sequence": [
    {"filter": ["even"]},
    {"filter": ["even"]}
  ]
}
```

3操作の例：

```json
{
  "sequence": [
    {"map": ["negate"]},
    {"map": ["negate"]},
    {"order": "ascending"}
  ]
}
```

これらの詳しい対象形式と件数は、`docs/policies/repetition_generalization_test_policy.md`で定める。

## 順序違いも訓練から除外する

操作の順序を区別しているため、選択した操作集合について、一部の順序だけを訓練に残すことはしない。

### 2操作の場合

操作`A`と操作`B`の組を組合せ汎化テストに選んだ場合、次の2通りを両方とも訓練から除外する。

```text
A → B
B → A
```

例えば、偶数だけを残す抽出と降順の並べ替えを選んだ場合は、次の両方を組合せ汎化テスト側に置く。

```json
{"sequence":[{"filter":["even"]},{"order":"descending"}]}
```

```json
{"sequence":[{"order":"descending"},{"filter":["even"]}]}
```

### 3操作の場合

異なる操作`A`、`B`、`C`の組を組合せ汎化テストに選んだ場合、次の6通りをすべて訓練から除外する。

```text
A → B → C
A → C → B
B → A → C
B → C → A
C → A → B
C → B → A
```

これにより、同じ操作集合の別順序が訓練データに残ることを防ぐ。

## 訓練から除外する5個の2操作ペア

組合せ汎化テスト用として、次の5個の2操作ペアを選ぶ。5組の間で単独操作が重ならないようにしている。

| ペアID | 操作A | 操作B |
|---|---|---|
| `pair-01` | `atomic-000001`: 偶数だけを残す抽出 | `atomic-000020`: 降順の並べ替え |
| `pair-02` | `atomic-000002`: 奇数だけを残す抽出 | `atomic-000011`: `k`を加える変換 |
| `pair-03` | `atomic-000004`: `k`以上を残す抽出 | `atomic-000023`: 末尾`k`個の切り出し |
| `pair-04` | `atomic-000014`: 2倍する変換 | `atomic-000021`: 現在順を反転する並べ替え |
| `pair-05` | `atomic-000017`: 絶対値を取る変換 | `atomic-000024`: 先頭から1個おきの切り出し |

各ペアについて、`A → B`と`B → A`の両方を訓練から除外する。

| ペア数 | 1ペア当たりの順序数 | 訓練から除外する2操作AST |
|---:|---:|---:|
| 5 | 2 | 10 |

## 3操作ASTから訓練除外するもの

選んだ各ペアについて、操作Aと操作Bの両方を含む3操作ASTをすべて訓練から除外する。

3個目の操作Cは、AとBを除いた22操作から選ぶ。A、B、Cの順序は次の6通りをすべて対象にする。

```text
A → B → C
A → C → B
B → A → C
B → C → A
C → A → B
C → B → A
```

したがって、1ペアから訓練除外する3操作ASTは次の132件になる。

```text
22 × 6 = 132件
```

5ペアは互いに単独操作を共有していない。1つの3操作ASTが、操作を共有しない2個のペアを同時に含むには4個の異なる操作が必要になるため、今回選んだ5ペアから得られる132件同士は重複しない。

| ペアID | 3操作ASTの選択条件 | 件数 |
|---|---|---:|
| `pair-01` | 偶数だけを残す抽出と降順の並べ替えを両方含む | 132 |
| `pair-02` | 奇数だけを残す抽出と`k`を加える変換を両方含む | 132 |
| `pair-03` | `k`以上を残す抽出と末尾`k`個の切り出しを両方含む | 132 |
| `pair-04` | 2倍する変換と現在順を反転する並べ替えを両方含む | 132 |
| `pair-05` | 絶対値を取る変換と先頭から1個おきの切り出しを両方含む | 132 |
| 合計 | 重複なし | **660** |

現在の12,144件の3操作ASTのうち、660件を組合せ汎化テスト用として訓練から除外する方針とする。残る3操作ASTは11,484件である。

```text
12,144 − 660 = 11,484件
```

2操作ASTについては、552件のうち10件を訓練から除外するため、残りは542件である。

```text
552 − 10 = 542件
```

同じ操作が連続する意味ASTは、これら5組とは別の`repetition`テストで扱う。今回の組合せ汎化テスト670件には含めない。

## 670件の抽出手法

既存の12,720件から、上記5ペアを含む意味ASTを次のコードで抽出する。

| 用途 | ファイル |
|---|---|
| 24個の単独操作と`atomic-*` IDの対応 | `data/semantic_asts/atomic_semantic_asts.jsonl` |
| 抽出元となる12,720件 | `data/semantic_asts/combined_semantic_asts.jsonl` |
| 抽出コード | `scripts/semantic_asts/extract_compositional_semantic_asts.py` |
| 抽出結果 | `data/semantic_asts/compositional_semantic_asts.jsonl` |

抽出は次の順序で行う。

1. `data/semantic_asts/atomic_semantic_asts.jsonl`を読み、5ペアの`atomic-*` IDを実際の単独操作ASTへ変換する。
2. `data/semantic_asts/combined_semantic_asts.jsonl`を先頭から順に調べる。
3. 2操作ASTでは、選択したペアの2操作を両方含むものを抽出する。これにより、`A → B`と`B → A`の2件が対象になる。
4. 3操作ASTでは、選択したペアの2操作を両方含むものを抽出する。3個目の操作と並び順を限定しないため、各ペアについて22操作×6順序の132件が対象になる。
5. 抽出元の`spec_id`と`semantic_ast`を変更せず、`test_suite: "compositional"`を追加する。
6. 抽出元と同じ並び順でJSONLへ保存する。

この処理は、操作の入出力関係が同じかどうかを実行結果から推測して選ぶものではない。方針で指定した5ペアを構文上含むかどうかだけで、既存の意味ASTから決定的に抽出する。意味的に等価な別ASTから生成されたPythonコードとの完全一致は、この段階ではなく「コード生成後の完全重複の除外」で判定する。

出力レコードの形式は次のとおりである。

```json
{"spec_id":"combined-000043","semantic_ast":{"sequence":[{"filter":["even"]},{"order":"descending"}]},"test_suite":"compositional"}
```

抽出コードは、保存前に次の条件をすべて検証する。1つでも満たさない場合はエラーにして、抽出結果を保存しない。

- 抽出元が12,720件である
- 抽出結果が670件である
- 2操作ASTが10件、3操作ASTが660件である
- 各ペアについて2操作ASTが2件、3操作ASTが132件、合計134件である
- 1件の意味ASTが複数の選択ペアに一致していない
- `spec_id`が重複していない
- `semantic_ast`が重複していない
- 抽出元に同じ操作を繰り返す意味ASTが混入していない
- 全レコードの`test_suite`が`compositional`である

2026年9月17日時点で、この手法により670件を`data/semantic_asts/compositional_semantic_asts.jsonl`へ抽出済みである。

## コード生成後の完全重複の除外

意味ASTの入出力関係が同じであることだけを理由に、意味AST全体を訓練候補から除外しない。各意味ASTから生成したコードは、`boku1-nano.md`の「データの検証と選抜」に従ってレコード単位で判定する。

具体的な判定手順と除外記録は、`docs/policies/code_duplicate_exclusion_policy.md`で定める。

次の場合は、該当する訓練レコードを採用しない。

- 訓練データ内に、完全に同じPythonコードを持つ別レコードがある
- 組合せ汎化テストの正解コードと、Pythonコードが完全に一致する

入出力関係が同じでも、生成されたPythonコードが完全一致せず、ほかの検証条件も満たすレコードは訓練候補に残す。コードの完全一致による除外はコード生成後に行うため、この段階で除外されるレコード数は事前に固定しない。
