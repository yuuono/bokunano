# 日本語言い換えテスト方針

## 1. 目的

訓練で見せていない日本語表現を使って、同じ意味ASTから正しいPythonコードを生成できるかを評価する。

単純操作の意味、Pythonコード、テストケースは変えず、日本語表現だけを未学習にする。訓練用表現とテスト専用表現の分離は、文字列規則や無作為抽出ではなく、作成者が意味と自然さを確認した人手選定結果で固定する。

## 2. 承認済み545件の分割

人間が承認した545件を次の二つへ分ける。

| 辞書区分 | 件数 | 用途 |
|---|---:|---|
| `train` | 522 | 訓練、検証、通常テスト、組合せ・反復・境界値テストの指示生成 |
| `test_only` | 23 | 言い換え評価候補として訓練から除外。うち21件を評価へ採用し、旧表記2件は評価からも除外 |

`test_only`は、操作ごとの先頭要素や乱数で自動選定しない。人手で選んだ23個の`expression_id`を[`build_approved_expression_dictionary.json`](../../config/build_approved_expression_dictionary.json)へ固定し、残り522件を`train`とする。

`test_only`の表現本文だけでなく、その`expression_id`も訓練指示、訓練用プロンプト、few-shot例、既存表現の参考例へ渡さない。接続形も同じ辞書区分として扱い、終止形だけを訓練側へ流用しない。

## 4. 候補32件と評価採用30件

承認済み辞書の`test_only` 23件と、人手追加9件を合わせた候補は32件である。ただし、後から表記を明示指定した2操作については、承認済み辞書側の旧表現を評価へ併存させない。

```text
承認済み545件内のtest_only: 23件
人手作成の辞書外表現:        9件
候補合計:                   32件
評価から除外する旧表現:      2件
評価採用:                   30件
```

評価から除外するのは次の2件である。レコードは生成来歴と訓練への非混入を維持するため承認済み辞書の`test_only`に残すが、言い換え評価指示には使わない。

| 操作ID | 除外する旧終止形 | 採用する指定終止形 |
|---|---|---|
| `atomic-000014` | 各要素を2倍にする | 各要素を二倍にする |
| `atomic-000015` | 全部を三倍する | 全部を3倍する |

採用する30件で24操作すべてを覆う。操作ごとの表現数は次のとおりである。

| 操作ID | 表現数 |
|---|---:|
| `atomic-000001` | 3 |
| `atomic-000002` | 3 |
| `atomic-000003` | 2 |
| `atomic-000013` | 2 |
| 上記以外の20操作 | 各1 |

候補32件の本文、接続形、表現IDは、訓練指示、validation、通常・組合せ・反復・境界値テスト、教師全文言い換えのfew-shot例へ一切渡さない。評価指示へ使用するのは除外2件を除く30件だけとする。

## 5. 全文指示への組み合わせ方

言い換え評価では2操作・3操作の組み合わせを扱わない。採用した30件の各表現について、その表現が表す1操作だけを持つ単独操作ASTを使い、表現1件につき全文指示を1文作る。したがって評価指示は合計30文である。1操作につき表現が複数ある場合は、表現ごとに別の1文を作る。

1操作文では`expression_ja`だけを使う。`connective_expression_ja`は表現辞書の来歴と将来の検査のために保持するが、言い換え評価の全文には使用しない。

外側の文テンプレートは、[`rule_generated_instruction_policy.md`](rule_generated_instruction_policy.md)の1操作規則と同じものを使う。

```text
kを使わない操作:
整数リストxsから{expression_ja}solve関数を書いてください。

kを使う操作:
整数リストxsと整数kを受け取り、{expression_ja}solve関数を書いてください。
```

各レコードは`split=test`、`test_suite=paraphrase`、`dictionary=test_only`とし、`expression_ids`には現在の1件だけを保存する。意味ASTの操作列長も必ず1とする。各操作の正解コードとhidden test入力は、その単独操作の意味を検証できる固定済みのものを使う。

`normal`の1,202意味ASTへの割り当て、2・3操作の接続形による結合、表現の直積は行わない。以前検討した1,202件の主評価集合と2,653件の全組合せ診断集合も作らない。この評価は複合操作の性能ではなく、未学習の単純操作表現を理解できるかだけを測る独立集合とする。

生成済み30文、出力ZIP、ハッシュ、再生成コマンドは、[言い換えテスト指示の生成結果](../results/paraphrase_test_instruction_results.md)へ記録する。

## 6. 懸念点と対処

### 辞書外9件の来歴

9件にはQwenの生成記録がない。Qwen生成と誤認しないよう、別JSONLへ保存し、`source=human_authored_out_of_dictionary`を必須とする。承認済み545件の`generation_record`を捏造しない。

### 短い表現の曖昧さ

`kを掛ける`は目的語を省略し、`その数と自らをかける`は前文脈へ依存する。外側テンプレートへ埋め込んだ30文すべてを最終確認し、単独操作の指示として意味を確定できない文は評価へ入れない。確認時は表現ID、操作ID、完成全文を対応付ける。

### トークナイザによる評価の混同

評価採用30件を学生モデルの訓練データだけでなく、トークナイザ学習コーパスにも入れない。言い換えテスト実行時には、30件の文字・subwordが未知トークンになる割合を別に集計する。未知トークンが多い場合は、「意味の言い換えに失敗した」のか「トークン化できなかった」のかを分けて報告する。

### 表現単位の未学習性

評価採用30件の全文字や単語が訓練側へ一度も現れないことまでは要求しない。要求するのは、終止形・接続形の完全な表現組とその表現IDを訓練へ入れないことである。したがって、このテストは完全な未知語テストではなく、未学習の操作表現を理解できるかを測る。

## 7. 分割の再現方法

公開済みCSVと生成来歴JSONLから、次を実行する。

```bash
uv run --python 3.12.12 python \
  scripts/instruction_generation/build_approved_expression_dictionary.py \
  --config config/build_approved_expression_dictionary.json \
  --overwrite
```

出力は次の2ファイルである。

| ファイル | 内容 |
|---|---|
| `data/instruction_dictionaries/approved_expressions.jsonl` | 545件すべてに`train`または`test_only`を付け、元の生成レコードも保持した利用用辞書 |
| `data/instruction_dictionaries/approved_expression_stats.json` | 総数、区分別件数、操作別件数、選定ID、辞書バージョン |

この2ファイルは公開CSVと来歴JSONLから再生成できる派生物なのでGit管理しない。人手選定の再現に必要な23件のIDは設定JSONとしてGit管理する。

## 8. 検査条件

分割処理は次を満たさない場合に停止する。

1. 公開CSVと来歴JSONLが545件で、行単位のID、操作ID、終止形、接続形が一致する。
2. 人手選定IDが23件で、すべて公開CSVに存在する。
3. `train=522`、`test_only=23`になる。
4. 23件が22操作を覆い、`atomic-000003`だけ2件、`atomic-000018`と`atomic-000021`は0件になる。
5. 出力各行が生成時の`generation_record`を保持する。
6. 人手追加JSONLが9件で、すべて`dictionary=test_only`、`source=human_authored_out_of_dictionary`である。
7. 23件と9件の表現IDが重複せず、候補合計32件になる。
8. 候補32件の終止形・接続形がtrain 522件の完全な表現組と重複しない。
9. 指定した旧表現2件が評価対象から除外され、評価採用が30件になる。
10. 言い換え評価指示が30件で、各レコードの操作列長と`expression_ids`長がともに1である。
11. 30件が24個の単独操作ASTをすべて覆い、2操作・3操作のASTを含まない。
