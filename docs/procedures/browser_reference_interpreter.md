# ブラウザ版の参照インタプリタ実行方式

2026-10-05 v13では、実行・比較欄をGitHub Pagesから外した。以下はリポジトリに保存しているv11の実装方式の記録である。関連する4ファイルは公開用の成果物から除外する。

## 目的と比較対象

生成されたPythonが、確認した操作の意味と一致するかを入力値で確認する仕組みである。Qwenの日本語の意味理解そのものを採点する機能ではない。

生成前に、検査済みCNLの操作IDを `web/semantic-ast.js` の `captureSemanticAst` でデータセット互換の意味ASTに変換する。例えば絶対値の後に降順へ並べる場合は次の形になる。

```json
{"sequence":[{"map":["abs"]},{"order":"descending"}]}
```

単独操作は原子AST、複数操作はsequence配列で表現し、操作の順序と重複を保存する。生成コードからASTを逆算せず、生成開始時にASTを凍結する。検証するコード文字列、意味AST、kの初期値はコードカードごとに保持する。別の指示やモデルに切り替えても、過去のコードの比較対象は変えない。

## 実行経路

1. `web/code-verification.js` が検証入力xsとkを検査する。
2. 専用の `web/verification-worker.js` を新しいWeb Workerとして起動し、コード・意味AST・xs・kを送る。
3. WorkerがPyodide 0.29.2を読み込む。PyodideはWebAssembly版のPython実行環境であり、処理はブラウザ内で行われる。
4. 同じ配信元から `reference_interpreter.py` と `verification_runtime.py` を取得し、Pyodideの仮想ファイルシステムに配置する。
5. `verification_runtime.verify_json` にJSONで検証要求を渡す。生成コードをJavaScriptへ翻訳しているわけではなく、実際のPythonコードをPythonとして実行する。
6. Python内で参照値と生成コードの戻り値を比較し、状態と表示用文字列をWorkerから返す。
7. 終了時にはWorkerを破棄する。再実行でも別のWorkerを使うため、前の実行で変更された変数や入力は引き継がない。

Pyodideの取得元は `https://cdn.jsdelivr.net/pyodide/v0.29.2/full/`。初回に実行環境のダウンロードが必要になる。利用者のxs・k・生成コードを外部の実行APIに送る処理はない。

## 参照値の計算

元の実装はリポジトリ直下の `reference_interpreter.py`。ブラウザ用の同名ファイルはその完全なコピーであり、テストで内容の一致を検査している。

通常の1〜3操作では `reference.interpret(semantic_ast, xs, k)` を呼ぶ。この関数はコードを生成せず、意味ASTを先頭から直接実行して整数リストを返す。

- 抽出：`operator` と `itertools.compress`
- 数値変換：`operator` とPython組み込みの `map`
- 昇順・降順：ヒープを使った取り出し
- 現在の順序の反転：`deque.pop`
- 切り出し：`itertools.islice`、`deque(maxlen=k)`

4操作はWebデモ側の追加対応である。`verification_runtime._reference_result` が最初の入力を一度検査し、既存の `_apply_operation` ハンドラを4回順に適用する。途中の値が元の入力範囲を超えることは許可する。学習・評価用の参照インタプリタの1〜3操作という契約自体は変更していない。

## 生成コードの実行

生成コードはPythonの `ast.parse` で構文を検査してから、許可した組み込み関数だけを持つ新しい名前空間でコンパイル・実行する。続いて `solve(list(xs), k)` を呼ぶ。関数に `k=3` のような初期値があっても、検証時に指定したkを明示的に渡す。

対象は `solve(xs, k)` 関数1つとリスト処理用の構文に限る。import、属性アクセス、再帰、任意の関数呼び出し、入れ子の関数などは実行前に拒否する。これは一般用途のPython実行サービスではない。対応範囲外のコードは、意味が正しそうであっても検証エラーとなる。

実行ステップは50,000、rangeの長さは1,000、コード長は16,000文字、結果の長さは1,000要素、結果の整数は1,024ビットまでに制限する。読み込みは60秒、実行は5秒で打ち切り、Workerを停止する。停止操作でもWorkerを破棄する。

## 入力範囲と結果

既存の参照仕様に合わせ、xsは−100〜100の整数を0〜20個、kは1〜10の整数とする。空リストも受け付ける。boolや小数は整数として扱わない。

両方の実行にはそれぞれ入力のコピーを渡す。整数の比較はPython内で行い、大きな整数をJavaScriptの浮動小数点数に変換しない。結果は `repr` による文字列として返す。

| 状態 | 意味 |
|---|---|
| match | このxs・kについて、生成コードと参照値が一致した |
| mismatch | 生成コードは実行できたが、参照値と異なった |
| code_error | 構文検査、実行、戻り値の検査のいずれかで生成コードが失敗した |
| reference_error | 参照側で入力や意味ASTを実行できなかった |

生成コードでエラーが起きても、計算できた参照値は残す。一致はその入力についての確認であり、全入力の正しさや元の自由文の解釈の正しさを保証しない。
