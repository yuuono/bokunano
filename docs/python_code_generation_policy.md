# Pythonコード生成器と構造的変種の作成方針

## 目的

意味ASTから、次の固定シグネチャを持つPython関数を機械的に生成する。

```python
def solve(xs: list[int], k: int) -> list[int]:
    ...
```

同じ意味ASTから、意味を変えずに複数のコード表現を生成し、学習データの表面的な偏りを減らす。生成コードはすべて実行検証し、参照インタプリタと同じ結果になったものだけを採用する。

この文書では、コード生成器の責務、参照インタプリタからの独立性、構造的変種、検証方法、保存するメタデータを定める。日本語指示の生成は対象外とする。

## 入力と出力

入力は、[単独操作の意味AST定義](atomic_semantic_asts.md)に従う単独操作、または1〜3個の操作を格納した`sequence`形式の意味ASTとする。

```json
{
  "sequence": [
    {"filter": ["ge_k"]},
    {"map": ["mul_const", 2]},
    {"order": "ascending"}
  ]
}
```

出力は、`solve`関数を1個だけ含むPythonソースコードと、生成に使った構造的変種の情報とする。

```python
def solve(xs: list[int], k: int) -> list[int]:
    values = [x for x in xs if x >= k]
    values = [x * 2 for x in values]
    return sorted(values)
```

生成器は意味ASTの`sequence`を先頭から順番に処理する。操作の並び替え、削除、重複の除去は、意味が同じに見える場合でも通常の生成処理では行わない。

## 参照インタプリタからの独立性

コード生成器と[参照インタプリタ](reference_interpreter.md)に同じ誤りが入ることを避けるため、両者を独立した実装にする。

- コード生成器から`reference_interpreter.py`をimportしない
- コード生成器から`interpret`を呼び出さない
- 各操作を実行する関数や条件判定関数を両者で共有しない
- 参照インタプリタの途中結果を使ってコードを組み立てない
- 参照インタプリタは整数リストを直接処理し、コード生成器はPythonの式または文を生成する
- 共有してよいものは、意味ASTの公開仕様、操作名、入力条件などの宣言的な定義に限る

参照インタプリタでは、生成対象外の`itertools.compress`、複数イテラブルの`map`、`heapq.heapify`と`heapq.heappop`、`collections.deque`、`itertools.islice`を使用する。コード生成器は参照側の実装表現に制約されず、この文書で許可した内包表記、`for`ループ、スライス、`sorted`、`reversed`などをすべて生成候補にできる。具体的な分離方針は[参照インタプリタ](reference_interpreter.md)で定める。

生成器の正しさは、生成器自身のロジックでは判定しない。別の検証処理が生成コードを実行し、その結果を参照インタプリタの結果と比較する。

## 基本的な生成手順

コード生成は次の順序で行う。

1. 意味ASTの形、操作数、操作名、引数を検証する。
2. 単独操作を、内部では長さ1の操作列として扱う。
3. 使用可能な構造的変種から`style_id`と各変種を決める。
4. 操作列を順番にPythonの式または文へ変換する。
5. 固定シグネチャを含む関数全体を組み立てる。
6. `ast.parse`で構文を確認する。
7. 構文の許可リスト、安全性、長さ、シグネチャを確認する。
8. 生成コードを実行し、参照インタプリタと比較する。
9. 検証済みコードだけを保存する。

未知の操作、引数不足、余分なキー、範囲外の定数を見つけた場合は、推測してコードを生成せずエラーにする。

## 各操作のコード化

コード生成器は24個の操作について、参照インタプリタとは別にPython表現を定義する。

### 抽出

抽出は、内包表記または`for`ループで表現する。

| 操作 | 条件式 |
|---|---|
| `even` | `x % 2 == 0` |
| `odd` | `x % 2 != 0` |
| `gt_k` | `x > k` |
| `ge_k` | `x >= k` |
| `lt_k` | `x < k` |
| `le_k` | `x <= k` |
| `multiple_of_k` | `x % k == 0` |
| `positive` | `x > 0` |
| `negative` | `x < 0` |
| `zero` | `x == 0` |

### 変換

変換も、内包表記または`for`ループで表現する。

| 操作 | 要素の式 |
|---|---|
| `add_k` | `x + k` |
| `sub_k` | `x - k` |
| `mul_k` | `x * k` |
| `mul_const, 2` | `x * 2` |
| `mul_const, 3` | `x * 3` |
| `negate` | `-x` |
| `abs` | `abs(x)` |
| `square` | `x * x`または`x ** 2` |

### 並べ替え

| 操作 | 使用できる表現 |
|---|---|
| `ascending` | `sorted(values)` |
| `descending` | `sorted(values, reverse=True)`、`sorted(values)[::-1]` |
| `reverse` | `values[::-1]`、`list(reversed(values))` |

`descending`は値の大小による降順整列であり、`reverse`は現在の並びを反転する操作である。この二つを同じ操作として扱わない。特に、`values[::-1]`だけで`descending`を表現してはいけない。

### 切り出し

| 操作 | 使用できる表現 |
|---|---|
| `take_first_k` | `values[:k]` |
| `take_last_k` | `values[-k:]` |
| `every_other` | `values[::2]` |

`k`は1〜10であるため、`values[-k:]`は空リストと短いリストについても期待する意味になる。

## コードの構造的変種

### 内包表記と`for`ループ

`filter`と`map`には、少なくとも次の2形式を用意する。

```python
values = [x for x in values if x % 2 == 0]
```

```python
selected = []
for x in values:
    if x % 2 == 0:
        selected += [x]
values = selected
```

安全性検査で属性アクセスを禁止するため、通常ループでは`selected.append(x)`を使わず、`selected += [x]`を使う。入力`xs`は変更しない。

1つの関数内ですべてを内包表記にする形式、すべてをループにする形式、操作ごとに両者を切り替える混合形式を生成候補にできる。ただし、混合形式は各形式の基本検証が完了してから追加する。

### 一時変数の有無

一時変数を使わない形式では、各操作の式を処理順どおりに入れ子にして、最後に直接`return`する。

```python
def solve(xs: list[int], k: int) -> list[int]:
    return sorted([x * 2 for x in [x for x in xs if x >= k]])
```

一時変数を使う形式では、操作ごとに結果を代入する。1個の変数を再利用する形式と、段階ごとに新しい変数を使う形式を用意する。

```python
def solve(xs: list[int], k: int) -> list[int]:
    filtered = [x for x in xs if x >= k]
    doubled = [x * 2 for x in filtered]
    ordered = sorted(doubled)
    return ordered
```

`for`ループ形式は出力リストを保持する必要があるため、完全な「一時変数なし」の対象にはしない。

### 変数名

あらかじめ承認した名前の組から選ぶ。

- 処理中のリスト: `values`、`items`、`result`、`current`
- 新しいリスト: `selected`、`mapped`、`output`、`next_values`
- 要素: `x`、`value`、`item`、`number`

Pythonの予約語、組み込み関数名、`xs`、`k`との衝突、同じスコープで意味が曖昧になる重複は許可しない。意味ASTや日本語指示に含まれる文字列を、そのまま識別子として埋め込まない。

### 1行形式と複数行形式

「1行形式」は、関数本体を1個の`return`文で表す形式とする。`def`文まで物理的な1行に詰め込む形式は生成しない。

「複数行形式」は、各操作を代入文またはループとして順番に記述し、最後に`return`する。意味ASTの操作順をコード上でも追跡しやすいため、生成器の初期実装では複数行形式を基準とする。

### コメント

コメントは承認済みの短い定型文だけを使用し、意味を追加または変更しない。

```python
# k以上の値だけを残す
# 各要素を2倍する
# 昇順に並べる
```

コメントなし、関数全体を説明するコメント、各段階を説明するコメントを変種とする。コメント内に、コードが実行していない処理を書いてはいけない。

### 型注釈

課題の固定シグネチャを守るため、`solve`の引数と戻り値の型注釈は常に残す。型注釈の有無による変種は、ローカル変数だけを対象にする。

```python
result: list[int] = []
```

これにより、型注釈の表現差を含めながら、すべての生成コードを同じ公開インターフェースで呼び出せる。

### 降順と逆順の表現

降順には次の2形式を用意する。

```python
sorted(values, reverse=True)
sorted(values)[::-1]
```

現在の並びの反転には次の2形式を用意する。

```python
values[::-1]
list(reversed(values))
```

`ascending`の直後の`reverse`を`sorted(..., reverse=True)`へまとめるような操作間の書き換えは、基本生成器には入れない。後から追加する場合は、書き換え規則を個別に列挙し、通常の逐次形式とは別の`rewrite_id`を付け、参照インタプリタとの比較を必須とする。

## 変種の組み合わせ方

すべての変種の直積を生成すると件数が急増し、単純なASTほど過剰に増えるため、次の方式を採用する。

1. 各変種を構造化した`style_spec`として表す。
2. 意味ASTと両立する候補だけを列挙する。
3. `semantic_hash`、`style_id`、固定seedから決定的に候補を選ぶ。
4. 1つの意味ASTから採用する最大件数を定める。初期値は最大20件とする。
5. 全体で内包表記、ループ、一時変数、変数名、コメントなどの出現数を集計し、偏りが大きい形式を間引く。

同じ入力とseedからは、実行のたびに同じコードが生成されるようにする。ランダム選択を使う場合も、グローバルな乱数状態には依存しない。

`style_spec`の例を次に示す。

```json
{
  "style_id": "staged-loop-0007",
  "collection_form": "for_loop",
  "temporary_form": "fresh_names",
  "name_set": "descriptive",
  "layout": "multi_statement",
  "comments": "per_stage",
  "local_annotations": true,
  "descending_form": "reverse_keyword",
  "reverse_form": "slice"
}
```

単一の`code_style`文字列だけに全情報を詰め込まず、集計可能な個別フィールドとして保持する。

## 構文と安全性の制限

生成コードは、固定テンプレートと許可済みの演算子だけから組み立てる。その上でPython ASTを調べ、少なくとも次を確認する。

- トップレベルには`solve`関数が1個だけ存在する
- 引数が`xs`と`k`の2個で、固定の型注釈と戻り値注釈を持つ
- `import`、属性アクセス、ラムダ、クラス、追加関数、`while`、例外処理を含まない
- `eval`、`exec`、`open`、動的な組み込み関数参照を含まない
- 呼び出せる関数を`sorted`、`abs`、`reversed`、`list`に限定する
- 定数は意味ASTとテンプレートが要求する整数、文字列、`True`、`False`、`None`に限定する
- `xs`へ代入せず、入力リストを変更しない
- 生成コードの文字数またはトークン数が設定した上限以内である

実行時の名前空間も必要最小限にし、許可した組み込みだけを渡す。ただし、名前空間の制限だけを安全性の根拠にせず、実行前のPython AST検査を必須とする。

## 実行検証

構文検査を通過した各コードについて、別の検証プログラムが次を確認する。

1. 制限時間内にコンパイルと実行が完了する。
2. `solve`を指定した`xs`と`k`で呼び出せる。
3. 戻り値が整数だけを含む`list`である。
4. 呼び出し後も入力`xs`が変更されていない。
5. 参照インタプリタの戻り値と完全一致する。
6. 同じコードを同じ入力で複数回呼び出しても結果が変わらない。

検証入力には、各単独操作の期待値を人手で定めた固定例、複数操作用の決定的なランダム例、空リスト・1要素・負数・ゼロ・重複値・`k`の境界値などを含める。1件でも不一致、例外、時間超過があれば、そのコードは採用しない。

生成コードの完全重複は、[生成コードの完全重複を訓練データから除外する方針](code_duplicate_exclusion_policy.md)に従って、実行検証後に除外する。

## 保存するデータ

生成した各コードについて、少なくとも次を保存する。

```json
{
  "spec_id": "combined-000001",
  "semantic_ast": {},
  "reference_code": "def solve(...):\n    ...",
  "style_id": "staged-loop-0007",
  "style_spec": {},
  "generator_version": "...",
  "generator_seed": 0,
  "semantic_hash": "...",
  "code_hash": "...",
  "verification": {
    "syntax_ok": true,
    "ast_safe": true,
    "signature_ok": true,
    "tests_passed": true,
    "input_unchanged": true,
    "timeout": false
  }
}
```

`code_hash`は、保存する`reference_code`のUTF-8バイト列に対するSHA-256とする。完全重複の最終判定では、ハッシュだけでなくコード文字列全体も比較する。

## 実装の進め方

初期実装では、誤りを切り分けやすい順に機能を追加する。

1. 複数行、内包表記、1個の作業変数という基準形式で24操作に対応する。
2. 単独操作と1〜3操作の全意味ASTを実行検証する。
3. 直接`return`する1行形式を追加する。
4. `for`ループ形式を追加する。
5. 変数名、コメント、ローカル型注釈の変種を追加する。
6. 降順と逆順の等価表現を追加する。
7. 必要な場合だけ、明示的な操作間書き換えを追加する。
8. 形式別の件数を集計し、均等抽出と完全重複除外を行う。

新しい変種は、一度に複数追加せず、変種ごとの固定テストと全意味ASTに対する比較試験を通してから有効にする。

## 完了条件

コード生成器は、次をすべて満たした時点で完成とする。

- 24個の単独操作をすべて生成できる
- 1〜3操作の意味ASTについて、操作順を保ったコードを生成できる
- 参照インタプリタの実装をimportまたは再利用していない
- 規定した各構造的変種を少なくとも1件生成できる
- 同じseedから同じコードを再生成できる
- 全生成コードが構文、安全性、シグネチャ、時間、入力不変性の検査を通る
- 全検証入力で参照インタプリタと一致する
- 形式別の生成件数と不採用理由を集計できる
- 完全重複除外後に、訓練コードと組合せ汎化テスト正解コードの積集合が空である
