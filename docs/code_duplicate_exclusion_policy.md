# 生成コードの完全重複を訓練データから除外する方針

## 目的

組合せ汎化テストの意味ASTから生成した正解Pythonコードが、別の意味ASTから生成した訓練コードに完全に同じ文字列として入ることを防ぐ。

意味ASTの入出力関係が同じであることだけを理由に、意味AST全体を訓練候補から除外しない。同じ意味ASTから複数の等価コードを生成して検証した後、完全に同じPythonコードを持つレコードだけを訓練候補から除外する。

## 問題になる例

次の意味ASTは訓練候補に残る。

```json
{"sequence":[{"filter":["even"]},{"order":"ascending"},{"order":"reverse"}]}
```

```json
{"sequence":[{"order":"ascending"},{"order":"reverse"},{"filter":["even"]}]}
```

一方、組合せ汎化テストには次の意味ASTがある。

```json
{"sequence":[{"filter":["even"]},{"order":"descending"}]}
```

```json
{"sequence":[{"order":"descending"},{"filter":["even"]}]}
```

コードの構造的変換で、昇順の並べ替えと現在順の反転を`sorted(..., reverse=True)`として表現すると、訓練候補から生成したコードが、組合せ汎化テスト側で生成したコードと完全に同じになる場合がある。

ただし、同じ意味ASTから生成したすべてのコードが完全一致するわけではない。例えば次の逐次形式は、操作を3段階のまま表現している。

```python
def solve(xs: list[int], k: int) -> list[int]:
    result = [x for x in xs if x % 2 == 0]
    result = sorted(result)
    result = list(reversed(result))
    return result
```

次の形式まで変換された場合は、組合せ汎化テスト側のコードと完全一致する可能性がある。

```python
def solve(xs: list[int], k: int) -> list[int]:
    result = [x for x in xs if x % 2 == 0]
    result = sorted(result, reverse=True)
    return result
```

したがって、意味ASTを一括して除外するのではなく、生成されたコードをレコード単位で判定する。

## 完全一致の定義

データレコードの`reference_code`に保存するPythonコード文字列全体が一致する場合を、完全一致とする。

- 関数定義を含むコード文字列全体を比較する
- 意味ASTや実行結果だけでは判定しない
- 変数名、空白、改行、コメント、型注釈などが異なり、コード文字列全体が一致しない場合は完全一致としない
- ハッシュ値を使って検索する場合も、最後にコード文字列そのものが一致することを確認する

## 処理する順番

1. 日本語指示やPythonコードを生成する前に、意味AST単位で訓練・検証・テストへ分割する。
2. 訓練側と組合せ汎化テスト側の各意味ASTから、規定された構造的変換によって複数のPythonコードを生成する。
3. 各コードについて、構文、安全性、関数シグネチャ、実行時間、参照インタプリタとの一致を検証する。
4. 検証を通過した組合せ汎化テスト側の全コードを、完全一致確認用の集合に登録する。
5. 検証を通過した各訓練レコードの`reference_code`を、組合せ汎化テスト側のコード集合と比較する。
6. 完全に同じコードが見つかった訓練レコードだけを除外する。
7. 訓練データ内でも、完全に同じコードを持つレコードが複数ある場合は1件だけを残す。
8. 完全重複の除外後に、意味AST、コード形式、日本語テンプレートなどの件数を均す。

## 除外するもの

次のいずれかに該当する訓練レコードは採用しない。

- `reference_code`が組合せ汎化テスト側の生成コードと完全一致する
- `reference_code`が訓練データ内の別レコードと完全一致する

## 除外しないもの

次のものは、それだけを理由に訓練候補から除外しない。

- 組合せ汎化テストの意味ASTと入出力関係が同じ意味AST
- 実行結果は同じだが、Pythonコード文字列が異なるレコード
- 内包表記と通常の`for`ループなど、コード形式が異なるレコード
- 一時変数、変数名、コメント、型注釈などが異なり、コード文字列全体が一致しないレコード

これらは、`boku1-nano.md`にあるほかの検証条件をすべて満たす場合、訓練候補に残す。

## 除外記録

除外した訓練レコードについて、少なくとも次を記録する。

```json
{
  "spec_id": "...",
  "semantic_ast": {},
  "code_hash": "...",
  "matched_test_spec_id": "...",
  "reason": "test_code_exact_duplicate"
}
```

訓練データ内の重複を除外した場合は、`reason`を`train_code_exact_duplicate`とする。

## 最終確認

データ作成後に、次の条件を機械的に確認する。

```text
訓練コードの集合 ∩ 組合せ汎化テスト正解コードの集合 = 空集合
```

あわせて、訓練データ内に完全に同じコードが複数残っていないことを確認する。これらの確認結果と除外件数をデータ生成時の記録へ保存する。
